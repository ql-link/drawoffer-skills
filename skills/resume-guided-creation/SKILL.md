# 引导创建简历

引导的读者是第一次写简历的学生。目标是让用户少打字、不被问烦，最后拿到一份可以投递的第一版。事实来源和禁止编造的规则见 [简历证据方法](../resume-evidence-method/SKILL.md)，下面规定提问方式和成文方式。

## 怎么问

- 一次只问一件事；能给选项的给 2–3 个选项（学历、求职状态、经历类型），不能给选项的给一个回答示例。
- 已经知道的不再问：前面问到的、资料里读到的、用户上一轮说过的，直接拿来用，最多请用户确认一句。
- 资料里读到的信息先说“我从资料里看到……”，再请用户确认或补充，不要当成已确认的事实直接写入。
- 用户回答含糊时，追问一个能落到简历上的细节（时间、角色、用到的技术、做成了什么），不要连续追问三次以上同一段经历。
- 用户说“没有”“不记得”“先跳过”时接受，不劝说、不编造替代内容。

## 先问清基本信息

- 先把目标岗位、学校、专业、学历和毕业年份问齐，再开始写简历；这几项决定了后面每一段的写法和重点。
- 求职方向最多 3 个；方向太多时请用户选出最想投的一个作为主线。
- 不确定的信息不要先写进去，先问清楚。

## 怎么写

- 教育：一所学校一条，写明学校、学历、专业和起止时间；GPA、排名、主修课程作为补充条目，没有就不写。
- 技能：按类别分行写，例如“编程语言：Java（熟练）、Python（熟悉）”；熟练程度只用用户自己确认的说法。
- 经历：一段经历一条，写明公司、项目或组织名、角色，日期写到月；下面的 bullet 每条以动词开头，写“做了什么、怎么做、结果如何”，一条一件事，3–5 条为宜。用户没给出的数字不写，不用“显著提升”“大幅优化”这类空话代替。
- 个人总结：两三句，只概括简历里已经写出的事实和目标岗位，不加形容词堆砌。
- 不写模板占位文字，不写“XX”“示例”这类空缺标记；缺的内容直接不写。
- 语言跟随简历现有内容，日期格式统一为“2025.07”。
